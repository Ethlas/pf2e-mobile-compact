# Foundry VTT AI Content Policy Audit Skill

Use this skill whenever adding new features, reviewing pull requests, adding UI icons/assets, or preparing a module release for `pf2e-mobile-compact` to guarantee 100% compliance with the **[Foundry VTT AI Content Policy (Revised March 18, 2026)](https://foundryvtt.com/article/ai-policy/)**.

---

## 1. Compliance Checklist

### A. Prepared Media Assets (Sections 4.2 & 4.3)
1. **Check for Bundled Media Files**:
   - Verify no `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.mp3`, `.ogg`, `.wav`, `.mp4`, or `.webm` files have been generated by AI or added without human provenance.
   - If any media file is bundled, verify that `ASSET_PROVENANCE.json` exists in the project root and documents the human creator, source URL, and license for every file.
2. **Check SVG Usage (Section 4.2)**:
   - Ensure any `.svg` files or inline `<svg>` tags are genuine geometric UI icons (`< 10 KB`, no embedded base64 `<image>` tags or complex traced illustrations).

### B. Prepared Written Text & Third-Party Module API Delegation (Sections 1.1 & 4.1)
1. **Zero Duplicated Rules or Lore**:
   - Confirm that no PF2e compendium text, lore, item descriptions, or third-party module constants (`pf2e-kingmaker-tools`, `pf2e-dailies`) are copied into JS/HBS files.
   - Confirm all game math, rules descriptions, and Kingdom/Camping structures are retrieved dynamically at runtime from `game.pf2e`, `actor.system`, `fromUuid`, or companion module APIs (`kmApp._preparePartContext`).

### C. Software Code Comprehension & Anti-"Vibe Coding" (Sections 4.4 & 7)
1. **Modular File Size & Readability**:
   - `scripts/apps/mobile-sheet.js` must remain `< 700` lines.
   - Domain helpers must have clear responsibilities, descriptive JSDoc headers, and inline architectural explanations so the human author (`Ethlas`) can explain and maintain every line of code.
2. **Design Documentation & Commit History**:
   - Verify that `CHANGELOG.md` explains the architectural rationale and design decisions for every milestone.

### D. Runtime Code Safety & Package Categorization (Sections 5 & 6.6)
1. **No Unconfirmed Runtime Code Execution**:
   - Verify zero occurrences of `eval(` or `new Function(` in `scripts/`.
2. **No "Zero AI" Tag**:
   - Verify `module.json` and `README.md` do not claim `"Zero AI"` status.

---

## 2. Running the Automated AI Policy Audit

Run the static verification and AI policy compliance suite via Node.js:

```powershell
node scripts/verify.mjs
```

Section 7 of `scripts/verify.mjs` automatically enforces these checks locally and on every GitHub Actions Pull Request (`.github/workflows/ci-verify.yml`).
